# Security boundaries

Required before changing network requests, credentials, subprocesses, resource loading or reviewing an affected security boundary.

- Trace attacker-controlled bytes through decoding, normalization, interpolation and the final consumer. Include mail headers/bodies, MIME names, server responses, URLs, credentials and persisted settings. Base64 is transport, not sanitization.
- All network requests are made in Rust under `core/` (providers, `core/src/auth/`, `core/src/calendar/`, `core/src/contacts/`, `core/src/public_http/`). The TSX app makes none: it asks the backend through `src/backend/client.ts`. Keep it that way; a request added in TSX would bypass every check below. Subprocesses start with a fixed program and an argument vector, never a shell, and no sender or server data chooses the program: provider programs such as the HEY CLI through `core/src/process/`, AI agents from `core/src/agent/` (`provider.rs`, `opencode.rs`), the desktop opener for a stored attachment (`xdg-open` or `open`, `open_download` in `ext/omamail-native/src/lib.rs`), and the default-mail-client tools (`xdg-mime`, `xdg-settings`, `update-desktop-database`, `hyprctl` in `ext/omamail-native/src/mail_client.rs`).
- Sender-controlled requests (remote images and one-click unsubscribe) go through `core/src/public_http/`. It checks every DNS answer and connects only to those checked addresses, keeping TLS verification for the original hostname. A name check (`isPublicHost` in `src/mail/message/html.ts`) or a lookup followed by an independent resolution does not suffice; the TSX name check only decides what to ask for. No production fallback or environment bypass may weaken this. Configured mail and CalDAV servers may legitimately be private.
- Keep credentials out of argv, logs, world-readable settings and attacker-selected origins. Secrets live in the platform credential store through `core/src/credentials/` (`credentials.get`, `credentials.put`, `credentials.delete`). Some tokens do pass through TSX memory: `auth.token` hands the TSX a Gmail or Outlook access token; Outlook's device-code sign-in runs in TSX (`outlookSignIn` in `src/features/accounts/flows.ts`, `src/mail/providers/microsoft.ts`), which holds its access and refresh tokens until it stores the refresh token with `auth.store`; and `credentials.get` returns stored Google and Outlook refresh tokens. Google's sign-in saves its refresh token in Rust (`core/src/auth/callback.rs`) and returns only the access token. Microsoft 365 tokens never leave Rust. The TSX must never persist or log a token, and hands a refresh token only to `auth.store` or `credentials.put`. A Google OAuth client file is owner-only (0600) in the private config directory (`credentials.json`; `core/src/platform/app_config.rs`, read through `core/src/platform/private_fs/`, which refuses a file other users can read), never in settings. Pass credential-bearing error text through the provider's `redact` (`src/mail/providers/google.ts`, `imap.ts`, `microsoft.ts`) before it reaches a label.
- Resolve CalDAV event hrefs against the collection and refuse a change of scheme, host or port before reading credentials. `caldavEventUrl` in `src/mail/calendar/calendar.ts` refuses first, by returning an empty address; `event_url` in `core/src/calendar/mod.rs` refuses again before the credential lookup.
- Every network request needs a deadline and a size bound. In Rust that is the client's timeout or a `tokio::time::timeout` around the whole exchange, plus a byte limit checked while reading the body.
- Sender-selected requests never follow redirects: `core/src/public_http/` builds its client with no redirect policy, and one-click unsubscribe (`public.unsubscribe`) sends a fixed form body and reports only the status. The reader treats a 3xx as a refusal, not another destination (`src/features/reader/store.ts`). Unsubscribe destinations are taken from the `List-Unsubscribe` headers and checked in `core/src/mail/read_links.rs`; `src/mail/message/unsubscribe.ts` decides which offer to show.
- Message resource attributes and attachment paths remain security boundaries regardless of appearance preferences. Follow [message rendering](MESSAGE-RENDERING.md); never draw an original remote image URL. Render sender-written labels as plain text and remove line breaks from outgoing header values.
- Security tests must fail on the vulnerable behavior and assert no forbidden effect: process/network request, credential disclosure or file write. Cover sibling providers/callers, CR/LF/CRLF, trailing controls, NUL, malformed encodings and valid quotes/backslashes/Unicode/multiline bodies. Use controlled targets and synthetic credentials.
- Report tested versions and environment gaps. Distinguish confirmed exploits, demonstrated boundary violations and unverified delivery hypotheses. Synthetic Gmail resources do not prove Gmail delivers those bytes; a local test peer does not prove a real server's parsing or network behavior. State pre-existing limitations and the scope of a PASS; never claim a complete audit from a scoped fix.
